# Android calendar and release watch handoff

## Implementation

- `NexusMessageBridge` registers `NexusNative` with `WebViewCompat.addWebMessageListener` before the local page loads. It accepts only the exact `https://appassets.androidplatform.net` origin and main-frame messages. Envelope: `{v:1,requestId,method,params}`; success `{v:1,requestId,ok:true,result}`, failure `{v:1,requestId,ok:false,error:{code,message}}`; invalidation `{v:1,event:'calendar.changed'|'watch.changed',revision}`. Payload is a JSON string in `onmessage.data`. The existing legacy Android bridge remains for file/share/GitHub behavior.
- Calendar methods: `calendar.getPermission`, `calendar.requestPermission`, `calendar.getSources`, `calendar.getRange`, `calendar.getDetails`, `calendar.openSystemEvent`, `calendar.prepareInsert`. Range is at most 62 days with 250-item pagination; calendar queries run on a dedicated IO executor and results are rechecked for permission on the main thread. ContentObserver is scoped to resumed, permitted lifecycle; IDs issued by the current adapter are held only in memory. Insertion opens the system editor and reports `opened`, not saved. `onRequestPermissionsResult` handles calendar and notification permission responses.
- Watch methods: `watch.getState`, `watch.setSnapshot`, `watch.setApiKey`, `watch.requestNotifications`, `watch.checkNow`, `watch.markRead`, `watch.exportHistory`, `watch.restoreHistory`. Snapshot is generation guarded. `restoreHistory({events})` merges read and notification state by stable ID; previously unseen imported events are marked read and baseline so a restored history cannot generate old pushes. API credentials are entered in an Android dialog, encrypted under Android Keystore, and never returned to JavaScript.
- `ReleaseWorker` uses WorkManager's unique periodic six-hour job and unique one-off network-constrained job. It queries official `/v4/changes` streams with `country=se`, a comma-separated allowlisted group of selected `<provider>.subscription` catalogs, `show_type=series`, `change_type=new|removed|upcoming`, `item_type=season|episode`, explicit pinned `from`/`to`, ascending pagination, and an encoded cursor. At most six logical streams (change type × season/episode) are paged round-robin. A page's observed events and next cursor are committed atomically; the stream watermark advances only when `hasMore=false`. The response's `shows[change.showId].imdbId` is joined exactly to an enabled snapshot row, and only provider-confirmed subscription changes with explicit numeric season and episode are admitted. No season number is invented from `/shows` array position or global airdate. `new` timestamps are treated as catalog-change time; only known `upcoming` timestamps become `releaseDate`.
- Network execution has its own process-wide worker mutex; it does not hold the journal/configuration lock while waiting for HTTP. Every checkpoint and final notification section rechecks both configuration generation and credential generation. Concurrent read-state/history changes merge monotonically. A config/key change discards stale responses without resetting previously charged requests. Changing selected services translates retained-service checkpoints to the earliest retained pinned interval/watermark and re-queries it without reusing incompatible catalog cursors. Only newly enrolled series/providers receive the historical-notification baseline; existing providers do not lose their backlog. Concurrent explicit reads clear pending availability pushes even when merged during a network check. `restoreHistory` is idempotent: an unchanged archive causes neither a disk write nor `watch.changed`.
- Exact subscription evidence is checked by testable `WatchRules.evidenceNumbers`: explicit positive integer season/episode (zero/specials are excluded consistently with the shared contract), exact provider, matching item/change/series type, subscription offer, and non-future timestamps for `new`. Removed offers and corrected upcoming dates update existing stable records. Grouped notifications distinguish upcoming from available and include an episode number for a single episode. A newly available transition can still notify after its earlier upcoming announcement; explicit read actions clear that pending transition.
- Calendar pages/results reject revision changes as stale, and permission revocation rejects private results. Cancelled/declined filters retain provider rows whose optional status columns are null. `releaseDate` media entries open the system editor as one all-day event. Permanently denied calendar permission opens Android app settings only after the explicit permission button is pressed.
- The journal charges quota before each HTTP attempt and caps usage at 900 calls per UTC month, six pages per run. 401 suspends checks until the credential changes; 429 respects a bounded `Retry-After`; manual checks honor the same counter and 15-minute throttle. The journal reports partial streams. New series/provider enrollment, re-enablement, and first stream scan mark old observations read and suppress historical push. Notifications are grouped by series/provider/season, recheck the latest config and permissions, defer in quiet hours, and use a stable notification tag. MainActivity handles `#serier?item=...` on both cold and warm intents.

## Provider scope and limitations

Supported subscriptions are Netflix, Prime Video, Disney+, HBO Max and SkyShowtime. Viaplay and TV4 Play are reported unavailable. The documented upcoming feed is enabled for Netflix, Prime Video, Disney+ and HBO Max; SkyShowtime upcoming is reported unavailable. The source only exposes up to a 31-day range; a cursor that ages outside it is discarded with a history note, so a long offline period can have a coverage gap. Combined selected-service change feeds can be dense, so six pages per run and the fixed monthly cap can mean delayed or incomplete coverage; the state reports partial checking. No live API key or physical Android device was available to validate a provider response or system-calendar OEM behavior.

API contract checked against the provider's [Changes reference](https://docs.movieofthenight.com/resource/changes) and [official OpenAPI](https://github.com/movieofthenight/streaming-availability-api/blob/main/openapi.yaml).
